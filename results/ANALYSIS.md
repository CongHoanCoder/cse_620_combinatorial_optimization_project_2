## 5. Discussion prompts (map each to evidence above)

1. **Pivots vs n at fixed m=2**: the vertex set of {x >= 0 : Ax <= b} has
   dimension related to m; increasing n mostly adds candidate directions.
   Does the mean pivot count grow with n?  Point at the m=2 column of the
   pivot table and the `pivots_vs_n.png` figure.
2. **Pivots vs m at fixed n**: each extra constraint cuts the polyhedron and
   can create new vertices / longer pivot paths.  Compare rows of the
   pivot table for n=50 across m=2,6,10,14.
3. **Time vs pivots**: runtime should track pivot count almost linearly for
   dense tableau Simplex (each pivot costs O(m*n)).  Compare
   `time_vs_n.png` with `pivots_vs_n.png`.
4. **Infeasibility (mixed stress grid / special case)**: Phase I minimizes the
   sum of artificials; a strictly positive optimum means the constraint set
   is empty.  Point at `infeasible_parallel_constraints` and the
   mixed-status heatmap — infeasibility appears when >= rows demand more of
   a resource than <= rows allow.
5. **Unboundedness**: if a nonbasic variable has a positive reduced cost but
   no positive entry in its column, the LP has a feasible improving ray.
   Removing a bounding constraint (special case) opens that ray.
6. **Degeneracy / multiple optima**: several active constraints at a vertex
   force a basic variable to 0; a zero reduced cost on a nonbasic variable
   means alternative optima exist.  See degenerate_vertex_3active and
   multiple_optima_face.
7. **Sparsity**: a basic feasible solution has at most m nonzero variables in
   standard form, so optimal vertices are structurally sparse as n grows with
   fixed m.  In production planning / portfolio / logistics LPs this means
   few active products/assets/links — the zeros are the business insight.
